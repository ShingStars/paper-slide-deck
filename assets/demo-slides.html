/ PART 01

内容决定版式，组件服务表达

同一种纸感风格，容纳不同的信息关系

Hero

引入一个主题

用一句清晰的观点开场，说明这场讲述与听众的关系。

Window

保留原始代码

文件标签、深色窗口和复制反馈，承载可复用的代码内容。

Table

让差异可比较

对齐参数、方案和适用条件，减少来回查找的负担。

Grid / TwoColumn

呈现内容关系

平级分类用网格；对比、因果与代码解析可用双栏。

Stats

突出真实数据

只使用原文数据或可验证的计算，没有数字就选择其他组件。

QuoteCard / SlideNav

留下结论与路径

用信息卡片强调观点，通过真实页码和导航串起讲述。

同级组件共享字号、圆角和留白；页面不必采用相同布局。
/ PART 02

代码保持完整，解释紧随其后

Window + TwoColumn + 语义标签

presentation.json
presentation.json
{
  "title": "从文本到演示",
  "theme": "paper",
  "slides": [
    {
      "goal": "说明核心观点",
      "components": ["Hero"]
    },
    {
      "goal": "比较不同方案",
      "components": ["Table", "QuoteCard"]
    }
  ]
}
① title

先确定讲述主题。标题概括内容，不把原文第一行机械地当作封面。

② goal

每页有自己的任务。解释一个概念、比较一组方案，或收束一个结论。

③ components

按内容自由组合。页与页可以不同，组件也不需要全部出现。

④ 单文件交付

这段 JSON 仅说明编排思路。实际成品将样式、内容和交互全部内联到 HTML。

说明性配置示例，不是必须遵循的输入格式；代码可复制，较长内容可在窗口内滚动。
/ PART 03

把信息关系，映射为表达方式

一张通栏表格，也可以独立成为一页

原文特征优先考虑保留的重点
一个主题或关键结论Hero / QuoteCard观点、价值与必要上下文
程序、命令或配置Window + TwoColumn原始代码和逐段解释
可比较的方案或参数Table / TwoColumn一致的比较维度与条件
平级分类或模块Grid类别之间的边界与关系
有依据的数据Stats + QuoteCard数字、单位、口径和结论
编排原则

原文没有的数据不补造；内容过多就拆页，不靠缩小字号容纳整篇文章。

/ PART 04

统一风格，让每页各有重点

TwoColumn + QuoteCard

原始材料

完整，但未必适合演示

  • 观点、例子、细节混在一起
  • 长段落需要逐字阅读
  • 关系藏在文字顺序之中
展示网页

保留事实，重建阅读顺序

  • 每页围绕一个讲述目标
  • 用组件呈现分类与比较
  • 必要条件随结论一起保留

统一的是视觉语言，自由的是内容组织。
