# 视觉规范

来源是本会话中的米白纸感 JSON 讲解页面。继承其色彩、字体气质、细边框和代码窗口，而非继承截图上各组件的绝对坐标。PPT 式演示以 1440 × 810 的 16:9 画布呈现。

## Tokens

| Token | 值 | 用法 |
| --- | --- | --- |
| `--page-bg` | `#f4efe8` | 纸张外侧背景，极轻噪点 |
| `--paper` | `#faf7ef` | 页面和卡片底色 |
| `--ink` | `#33291f` | 标题和重要结论 |
| `--body` | `#807669` | 正文 |
| `--muted` | `#a29889` | 注释、页码 |
| `--line` | `#d7cdbf` | 纸张和表格边界 |
| `--rose` / `--rose-bg` | `#a56b62` / `#f0e2db` | 说明标签 |
| `--blue` / `--blue-bg` | `#507d98` / `#e2e7e8` | 分类或标识符 |
| `--yellow` / `--yellow-bg` | `#b88a29` / `#f2e6c6` | 文件名、条件 |
| `--cyan` / `--cyan-bg` | `#3e9295` / `#e0ede8` | 数组、流程、补充信息 |
| `--green` / `--green-bg` | `#688d7d` / `#e3e8df` | 结果或类型 |
| `--active` | `#a32922` | 导航选中态 |
| `--code-bg` / `--code-bar` | `#1a1a2e` / `#2a2b40` | Window |

固定视觉锚点：15px 左右的纸张圆角、2px 淡褐边框、柔和小阴影、纸张顶端淡玫瑰色虚线、标题下方短细线。不要变成荧光/玻璃/纯黑科技风，不加入高饱和大渐变。

## 字体和密度

- 标题：`"Times New Roman", "Noto Serif SC", "Songti SC", SimSun, serif`。正文：`Georgia, "Noto Serif SC", "Songti SC", SimSun, serif`。代码与标签：`Consolas, "Courier New", monospace`。字体缺失时使用系统回退，不依赖在线字体。
- 基准画布上的 Hero 标题 64–76px、常规标题 36–42px、正文 21–23px、标签 15px、代码 16–18px、表格 18–20px、脚注 14–16px。小于截图原版的字体不直接沿用，因为演示文稿需要可投屏阅读。
- 正文行高约 1.65；代码行高约 1.7；表格需要横向可比，不把每个单元格都包装成卡片。
- 桌面画布边距约 56px，组件间距 24–32px。尽量让同级内容对齐，文字长度和内容复杂度决定组件宽度。
- 长段落改写为有明确逻辑的小组，保留必要事实。Grid 一般每卡 2–5 行；表格复杂时拆成多页；完整代码可在 Window 内滚动，并让关键片段首屏可见。

## 自由组合

统一层级和间距即可，不要求统一排版。可以是左标题右结论的封面、通栏表格、上数据下引用、左代码右说明、三列分类、上下流程，或一页只有一句关键结论。

每页可选用 `.slide-heading`；Hero 页不必重复放常规页头。`.slide-body` 支持任意组合 `.stack`、`.two-column`、`.grid`、`.stats`，以及组件本身。`.slide-footer` 只放有用的来源或说明，不强制作者和版权。

默认不加入任何品牌、社交入口或“AI 生成”等无关信息。额外装饰不得挤占正文和投屏可读空间。
